# Frontend

**Русский** · [English](README.en.md)

Публичный сайт `vedal-med.ru` и ассистент Urania. Next.js 16, App Router, TypeScript, CSS Modules.

## Запуск

```bash
npm run dev
```

Без настройки поднимается на локальном контенте — бэкенд, база и Docker не
нужны. Чтобы работать против серверной части, скопируйте
[.env.example](.env.example) в `.env.local`.

## Откуда берутся данные

Каталог, новости и документы читаются из публичного API на сборке и
обновляются раз в пять минут — тот же срок, что бэкенд ставит в
`Cache-Control`. Поэтому падение бэкенда не роняет уже собранный сайт. Живой
бэкенд нужен только формам и Урании: они ходят из браузера.

| `NEXT_PUBLIC_API_URL` | Каталог, новости, документы | Формы и Урания |
| --- | --- | --- |
| не задан | `content/*.ts` | честно сообщают, что отправка не подключена; Урания отвечает локальными подсказками |
| задан | публичное API; если оно не ответило, **сборка падает** | `POST /api/forms/v1/leads` и `POST /api/assistant/v1/ask` |

Сборка падает намеренно: тихо подставить захардкоженный каталог опаснее, чем
не собраться, — снятая с публикации позиция уехала бы на прод.

Бэкенду нужно разрешить источник сайта: переменная `VEDAL_ALLOWED_ORIGINS`
на его стороне, см. [backend/README.md](../backend/README.md).

## Что сделано

Девять экранов сайта, чат Урании, формы заявок. Источник вёрстки —
[prototypes/urania-web-interface.html](../prototypes/urania-web-interface.html),
требования — [docs/frontend](../docs/frontend).

## Структура

- `app/` — маршруты и глобальные стили.
- `components/` — шапка, подвал, формы, блоки ассистента.
- `lib/api.ts` — чтение публичного API на сервере.
- `lib/submit.ts` — отправка заявок и вопросов Урании из браузера.
- `content/*.ts` — весь текст сайта и запасной источник данных.
  Незаполненные факты помечены `AWAITING`.

## Правила контента

Не выдумывать цены, характеристики, сертификаты и клинические заявления
([HANDOFF.md](../HANDOFF.md)). Недостающие данные — `ожидает уточнения` в `content/site.ts`.

Работа ведётся в ветке `front`.
