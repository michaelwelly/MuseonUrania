## 1. Что показываем заказчику

1. Публичная витрина VEDAL: главная, каталог, продукты, сервис, производство, документы, новости, контакты.
2. Навигация уже учитывает последние договоренности: добавлены `Сервис` и `Новости`.
3. На главной есть коммерческий фокус: запрос КП, каталог, направления, продукты, производство, документы, новости.
4. Urania заложена как AI-ассистент VEDAL: публичный режим по открытым материалам, закрытый режим после логина.
5. Админка предусмотрена для управления страницами, продуктами, документами, новостями и SEO-метаданными.

3. Backend `portal` собрался успешно: все 14 Maven-модулей завершились `SUCCESS`.

5. После локального `chmod +x` Postgres поднялся и стал `Healthy`.
6. `portal` ответил `UP` на `http://localhost:8081/actuator/health`.
7. Production `site` в compose завис на `next build` при лимите Docker Desktop около 1.93 GB RAM.
8. Для презентации поднят отдельный frontend dev-контейнер на `http://localhost:3002`, главная отдает `HTTP 200 OK`.

## 4. Риски перед VM-деплоем

1. В репозитории нужно зафиксировать executable bit для `backend/db/init/10-runtime-role.sh`: `100644 => 100755`.
2. Для полного локального compose-профиля нужно поднять лимит Docker Desktop минимум до 4-6 GB RAM.
3. `npm ci` показал `1 high severity vulnerability`; перед production надо прогнать `npm audit` и принять решение.
4. Production build сайта зависит от живого публичного API на этапе сборки; это осознанная архитектура, но ее надо отдельно проверить на VM.
5. Swagger и admin e2e надо перепроверить после стабильного полного запуска всего стека.

## 5. Демо-маршрут на встречу

1. Открыть витрину: http://localhost:3002
2. Показать главную: позиционирование, CTA, направления, продукты, документы, новости.
3. Перейти в `Продукция`: показать каталог и продуктовые карточки.
4. Перейти в `Сервис`: показать, что гарантия/сервис вынесены в отдельный раздел.
5. Перейти в `Документы`: объяснить разделение public/private.
6. Показать вход для сотрудников как будущий закрытый контур.
7. Объяснить Urania: публичные ответы по открытым материалам, после логина - поиск по внутренним документам.

## 6. Что нужно согласовать с НН

1. Финальные 10 продуктов первого релиза.
2. Какие документы можно публиковать открыто.
3. Какие документы internal/confidential.
4. Фото, видео, каталог Иннопрома, пресс-релиз.
5. Финальные формулировки по медицинским изделиям и сертификатам.
6. Кто согласует SEO-тексты и метаданные.
7. Нужен ли публичный AI-ассистент в первом релизе или только интерфейс-заглушка.

## 7. Предлагаемый статус для заказчика

Проект перешел от концепции и макетов к рабочему техническому контуру. На текущий момент готова демонстрационная публичная витрина, заложена админка, подготовлены backend-модули CMS/CRM/documents/assistant, локальная инфраструктура с Postgres, S3-compatible storage, Keycloak и Kafka. До production-деплоя требуется стабилизировать полный compose-запуск, исправить права init-скрипта БД, проверить e2e-сценарии форм/админки и закрыть вопросы по контенту.
