# Правила ведения документации

**Русский** · [English](documentation_rules.en.md)

## Документация ведётся на двух языках

**Каждый `.md` в репозитории существует в двух версиях:**

- `FILE.md` — русский, основной;
- `FILE.en.md` — английский, зеркало.

Первой строкой под заголовком в каждом файле стоит переключатель:

```markdown
# Заголовок

**Русский** · [English](FILE.en.md)
```

```markdown
# Title

[Русский](FILE.md) · **English**
```

Правила:

1. **Новый документ заводится сразу в двух версиях.** Односторонний файл —
   источник расхождения: через месяц никто не помнит, какая версия свежее.
2. **Правка вносится в обе версии одним коммитом.** Не «переведу потом».
3. **Русская версия ведущая.** При расхождении она права: заказчик, команда и
   технические решения — русскоязычные.
4. **Ссылки внутри английской версии ведут на английские файлы**
   (`[Spec](spec.en.md)`), внутри русской — на русские.
5. Имена файлов, пути, идентификаторы, названия таблиц, полей, топиков и
   маршрутов **не переводятся** ни в одной версии.
6. **Блоки кода копируются дословно**, включая русские комментарии и строки
   интерфейса: они должны совпадать с кодом в репозитории. Переводится только
   проза вокруг них.
7. Термины проекта не переводятся вольно — см. словарь ниже.

Исключение: `CLAUDE.md` и `AGENTS.md` в репозиторий не идут, они в `.gitignore`
как генерируемые тулингом. Поэтому правила лежат здесь, а не в них.

## Словарь терминов

| Русский | English | Не переводить как |
| --- | --- | --- |
| закрытый контур | closed contour | private circuit |
| открытый офис | open office contour | — |
| заявка / лид | lead | application, request |
| КП (коммерческое предложение) | quote | commercial proposal |
| согласовано / опубликовано | approved / published | — |
| датащит | datasheet | — |
| дверь (вход в API) | entry point, door | — |
| порт (интерфейс наружу) | port | — |
| журнал / аудит | audit log | journal |
| перечень документов | document listing | — |
| передача человеку | handoff to a human | — |
| ожидает уточнения | awaiting clarification | — |
| сид / наполнение каталога | seed | — |
| сборка сайта | site build | — |

Строки интерфейса и подписи, которые видит посетитель, в английской версии
остаются по-русски и берутся в кавычки: `«Запросить КП»`, `«ожидает уточнения»`.
Они не перевод, а факт о продукте.

## Как проверить, что ничего не разъехалось

Файлы без пары:

```bash
for f in $(git ls-files '*.md' | grep -v '\.en\.md$'); do b="${f%.md}"; [ -f "$b.en.md" ] || echo "нет EN: $f"; done
for f in $(git ls-files '*.en.md'); do b="${f%.en.md}"; [ -f "$b.md" ] || echo "нет RU: $f"; done
```

Русский текст, случайно оставшийся в английской версии вне блоков кода:

```bash
awk '/^```/{inb=!inb; next} {if(!inb) print FILENAME":"NR": "$0}' $(git ls-files '*.en.md') | grep '[а-яА-Я]'
```

Вторая проверка всегда выдаёт переключатель языка и намеренно сохранённые
строки интерфейса — их надо глазами отличить от забытого перевода.
