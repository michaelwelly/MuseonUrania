# Issue #110: переходы и обратный звонок

Ответы чата содержат `messages[].actions`: `navigate` либо `document`, название,
URL и `confirmationRequired: true`. Действия строятся только из сохранённых
источников ответа. Разрешены публичные разделы, карточки и endpoint публичного
документа; внешние URL, admin, query string и кодированные пути исключены.

Виджет сначала предлагает действие, затем спрашивает подтверждение. POST
`/api/assistant/v1/chat/navigation` принимает visitorKey, messageId, url,
confirmed=true. Сервер проверяет принадлежность сообщения разговору и наличие
URL среди предложенных источников. Подтверждение попадает в аудит без текста
переписки. Переход по сайту использует Next router и сохраняет общий layout
с открытым чатом. Документ открывается в отдельной вкладке через публичный API.
Ошибка подтверждения оставляет посетителя в разговоре.

Кнопка и точная команда «Позвоните мне»/«Перезвоните мне» раскрывают форму.
Передача происходит только после отправки контактов с отмеченным согласием.
Телефон и имя обязательны, почта для обратного звонка необязательна. Причина
и изделие выбираются посетителем; автоматически извлечённые контакты не
используются. При обращении до первого сообщения разговор создаётся при
отправке формы, после согласия.

`POST /api/forms/v1/leads/from-chat` дополнен callback, reason, productSlug.
Заявка содержит краткое содержание в виде последних реплик (без генерации
моделью), причину, изделие, следующий шаг и переписку. Согласие хранится
существующими полями consent_version и consent_at. Callback переводит
разговор в waiting, сохраняя attended, если сотрудник уже подключился.
В админской ленте над перепиской показан отдельный алерт с номером обращения.
После закрытия/обезличивания callback-алерт не показывается.

Приём заявки и привязка к разговору выполняются в одной транзакции с
пессимистической блокировкой открытого разговора. Ключ идемпотентности —
`chat:<conversationId>`: повтор возвращает первую заявку, не заменяет ранее
переданные контакты и не создаёт новое событие. Уведомление менеджеру идёт
через существующий outbox/LeadNotifier на `vedal.notifications.manager`
(по умолчанию sales@vedal-med.ru). Письмо содержит ссылку на заявку в админке;
контакты и переписка остаются в CRM. При пустой почте клиента подтверждение
ему не ставится в очередь. Staging/lab сохраняют свои настройки получателя.

Проверки: ChatNavigationTest, ChatLeadApiTest, LeadNotificationTest;
ChatNavigation.test.tsx, VedalinaChat.test.tsx, Thread.test.tsx.
Почтовые тесты используют тестовый транспорт и не отправляют реальные письма.
