# Сборка сайта при старте контейнера

**Русский** · [English](frontend_startup_build.en.md)

## Эксплуатационная особенность

Контейнер `vedal-site` не получает заранее собранный frontend-образ. При каждом
старте он выполняет `npm run build`. Деплой поднимает `portal` раньше `site`,
поэтому сборка сайта обращается к уже запущенному Public API через
`VEDAL_API_INTERNAL_URL`.

Это делает доступность и семантику build-time API частью запуска фронта:

- уже собранный сайт продолжает работать без портала;
- новый контейнер `site` не станет healthy, если обязательный build-time
  запрос получает неожиданную ошибку;
- локальный `next build` без `NEXT_PUBLIC_API_URL` и
  `VEDAL_API_INTERNAL_URL` не проверяет этот путь: `apiConfigured` ложен,
  и сборка использует запасные данные из `frontend/content/*.ts`.

## Авария 16 сентября 2026 года

Первая выкатка правок остановила публичный сайт примерно на десять минут.
Портал поднялся с выключенным публичным разделом документов и стал отвечать
`404` на `GET /api/public/v1/documents`. Запущенная следом сборка сайта
считала любой ответ не `2xx` фатальным. `npm run build` завершался ошибкой,
`vedal-site` оставался unhealthy, а публичные страницы отвечали `500`.
Автодеплой повторял тот же цикл каждые две минуты.

Хотфикс `6268307` зафиксировал различие состояний:

- `404` от перечня документов означает, что раздел закрыт выключателем;
  `fetchDocuments` возвращает пустой перечень, и сборка продолжается;
- `5xx` по-прежнему означает неисправность портала и останавливает сборку;
- два сценария закреплены тестами в `frontend/lib/api.test.ts`.

Разбор `404` следует уже применённой в проекте идиоме `fetchProduct` и
`fetchNewsEntry`: отсутствие или снятие публичного материала является
доменным состоянием, а не отказом инфраструктуры.

## Проверка перед выкаткой

1. Перед изменением публичного выключателя проверить его значение для обоих
   контейнеров по [таблице выключателей](public_feature_switches.md).
2. Запустить frontend-тесты, включая `frontend/lib/api.test.ts`.
3. Проверить сборку с настроенным внутренним API, а не только локальный режим
   с запасными данными.
4. После старта проверить health обоих процессов, коды основных страниц и
   ожидаемый код закрытых публичных дверей.
5. Ошибку `5xx` не преобразовывать в пустой контент: это скрыло бы настоящий
   отказ портала и выпустило неполную сборку.

Схема автодеплоя описана отдельно в [autodeploy.md](autodeploy.md).
