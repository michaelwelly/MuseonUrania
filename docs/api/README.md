# Спецификация API

**Русский** · [English](README.en.md)

Контракт, по которому сайт, админка и внешние интеграции ходят в серверную
часть портала.

| Файл | Зачем |
| --- | --- |
| `vedal-openapi.yaml` | Публичное API. Читать глазами, класть в задачу, смотреть в diff |
| `vedal-openapi.json` | То же, для Postman, Insomnia, генерации клиента, `editor.swagger.io` |
| `vedal-admin-openapi.yaml` | Админское API: контракт админки на фронте |
| `vedal-admin-openapi.json` | То же в JSON |
| `vedal.postman_collection.json` | Все двери одним импортом в Postman: 16 папок, 73 запроса |

## Две группы, и это не удобство раскладки

**`vedal-public`** — двери `/api/public`, `/api/forms`, `/api/assistant`.
То, по чему интегрируются снаружи; их читают те, у кого учётной записи портала
нет и не будет. Девять операций, пять разделов.

**`vedal-admin`** — `/api/admin/v1/**`. Двери правки и CRM: продукция,
категории, новости, документы с загрузкой файла, заявки, клиенты, сделки,
коммерческие предложения, история переписки, аналитика воронки, журнал,
изображения. Сорок шесть маршрутов, шестьдесят четыре операции.

Двери CRM здесь и только здесь. Клиентская база, суммы сделок и цены КП —
закрытый контур: в публичной группе их нет не потому, что их туда не
перечислили, а потому что публичной двери к ним не существует.

Разделение сделано затем, чтобы перечень дверей правки не уезжал в файл, который
отдают внешнему интегратору. Механически это `pathsToExclude` в `OpenApiConfig`,
а не «мы их сюда не перечислили»: `/api/**` покрывает и админку тоже, и без явного
исключения она попала бы в публичную группу молча.

Четвёртой двери при этом не появилось. Дверей по-прежнему три; у двери сотрудника
поменялась форма — вместо серверных страниц JSON.

## Источник истины — код, а не эти файлы

Спецификацию собирает springdoc из аннотаций контроллеров и записей DTO. Файлы
здесь — выгрузка, снятая руками для тех, кому неудобно поднимать приложение.

Отсюда правило: **менять их правкой в этом каталоге бессмысленно**. Контракт
меняется в `backend/src/main/java/ru/vedal/portal/`, после чего выгрузка
повторяется. Ограничения полей (допустимые типы форм, формат телефона,
минимальная длина обращения) в спецификацию попадают из аннотаций Bean
Validation — то есть из тех же проверок, которые работают на границе доверия.

Автоматической сверки нет: выгрузка может отстать от кода. Что не отстанет —
состав дверей: `OpenApiDocsTest` сверяет описанные пути с настоящими маршрутами
приложения **в обеих группах**, поэтому новая дверь не появится молча.

## Как админка предъявляет себя

Схема безопасности `keycloak`: токен доступа из realm'а в заголовке
`Authorization`. Роли портала — `portal-admin` и `portal-editor` в
`realm_access.roles`; токен без них проходит проверку подписи и получает `403`.
Это разные состояния, и интерфейс обязан их различать: «вход не выполнен»
и «портал не принял токен» выглядят одинаково только снаружи.

Запасной режим `vedal.iam.mode=local` — HTTP Basic поверх учётных записей
портала. В спецификации его нет намеренно: это режим разработки, а не контракт.

## Живая версия

Пока приложение поднято:

- Swagger UI — <http://localhost:8081/swagger-ui.html> (переключатель групп сверху)
- JSON — <http://localhost:8081/v3/api-docs/vedal-public>, <http://localhost:8081/v3/api-docs/vedal-admin>
- YAML — <http://localhost:8081/v3/api-docs.yaml/vedal-public>, <http://localhost:8081/v3/api-docs.yaml/vedal-admin>

Через шлюз те же адреса на `http://localhost:8080`.

В профилях `prod`, `staging` и `internal` спецификация и Swagger UI выключены:
перечень дверей — карта системы, по той же причине из actuator наружу отдаётся
только health. Контракт для интеграции берут отсюда или из dev, а не с боевого
адреса.

## Коллекция Postman

`vedal.postman_collection.json` — импорт одним файлом: **File → Import**.
Обе группы вместе, публичные двери и админские, разложены по папкам
в порядке работы.

Она собирается генератором из тех же `docs/api/*.json`, а не пишется руками:
набитая вручную, она разошлась бы с дверями на первой правке контракта.
Поэтому править её в этом каталоге так же бессмысленно, как выгрузку.

Чем отличается от простого импорта OpenAPI в Postman:

- **Токен вставлять не надо.** Скрипт коллекции берёт его в Keycloak
  по `username`/`password` из переменных и обновляет, когда протух.
  Токен живёт пятнадцать минут, и вставлять его руками на середине разбора
  сделки — ровно то, что отвлекает.
- **Идентификаторы едут между запросами.** «Отправить заявку» кладёт
  `leadId`, «Разобрать заявку в сделку» — `dealId` и `clientId`,
  «Завести КП» — `quoteId`. Папки работают по порядку сверху вниз,
  подставлять UUID руками не нужно.
- У публичных папок стоит `noauth`, форма заявки получает `Idempotency-Key`,
  необязательные параметры запроса приезжают выключенными.

Переменные коллекции — адрес шлюза, адрес Keycloak, учётная запись:

| Переменная | По умолчанию |
| --- | --- |
| `gateway` | `http://localhost:8080` |
| `keycloak` | `http://localhost:8180` |
| `username` / `password` | `editor` / `editor-local` |

Адрес по умолчанию — шлюз. Портал напрямую отвечает на `8081`, но тогда
включится CORS, которого через шлюз нет.

Прогнать без Postman, из командной строки:

```bash
npx newman run docs/api/vedal.postman_collection.json --folder "Формы" --folder "Админка: заявки"
```

## Как обновить выгрузку

```bash
docker compose -f backend/compose.yaml --profile app up -d --build
```

```bash
curl -s http://localhost:8081/v3/api-docs/vedal-public -o docs/api/vedal-openapi.json
curl -s http://localhost:8081/v3/api-docs.yaml/vedal-public -o docs/api/vedal-openapi.yaml
curl -s http://localhost:8081/v3/api-docs/vedal-admin -o docs/api/vedal-admin-openapi.json
curl -s http://localhost:8081/v3/api-docs.yaml/vedal-admin -o docs/api/vedal-admin-openapi.yaml
```

Коллекция пересобирается следом — она читает эти же файлы:

```bash
node backend/tools/postman-collection.mjs > docs/api/vedal.postman_collection.json
```

Без Docker приложение поднимается локально — `cd backend && ./mvnw spring-boot:run`,
базу всё равно даёт `compose.yaml`.

## Чего здесь нет

Страниц для браузера. Их у портала не осталось вовсе: серверная админка
на Thymeleaf удалена, а вместе с ней форма входа и cookie-сессия. Единственный
интерфейс, который портал рисует сам, — Swagger UI, и он про контракт, а не
про данные.

Автономной копии Swagger UI одним HTML-файлом. Такой файл собирается, но на
девять десятых состоит из минифицированного swagger-ui, и держать полтора
мегабайта чужого кода в репозитории незачем: тот же интерфейс приложение
отдаёт само.
