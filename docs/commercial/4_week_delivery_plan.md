# 4-Week Delivery Plan

## Week 1: Structure, Architecture, First Stand

Goal: approve site direction and show working first pages on a Yandex VM stand.

Planned work:

- Prepare 3 variants of website structure, hero, and sitemap.
- Select one variant with NN.
- Draw frontend/backend architecture in Excalidraw.
- Prepare frontend architecture and component plan for Egor.
- Finalize UX/UI direction.
- Deploy Yandex VM stand.
- Implement title page and 2-3 internal pages.
- Prepare NN review presentation and collect integration questions.

Acceptance gate:

- NN approves selected structure and page priority.
- Stand is reachable.
- Title page and 2-3 pages are visible and responsive enough for review.

## Week 2: Backend, CMS, S3, API

Goal: connect frontend and backend through documented API.

Planned work:

- Implement backend/CMS foundation.
- Configure S3-compatible media/document storage.
- Implement forms and lead-routing API.
- Prepare Swagger/OpenAPI contract.
- Connect frontend forms to backend.
- Define CRM handoff format.
- Collect available documentation for classification and future AI search.

Acceptance gate:

- API is documented in Swagger/OpenAPI.
- Forms work on the stand.
- S3 media/document flow is tested.
- NN approves integration direction and missing-data list.

## Week 3: SEO, Production Domain, Analytics

Goal: prepare production release and search/analytics baseline.

Planned work:

- Review full project scope and resolve content gaps.
- Configure SEO basics: metadata, semantic headings, sitemap, robots, structured content where appropriate.
- Configure cookie banner and public consent links.
- Deploy to production domain.
- Connect Yandex Metrica.
- Prepare Yandex Direct contract/workflow discussion.
- Separate public and internal document sets for publication and AI indexing.

Acceptance gate:

- Production domain is active.
- Yandex Metrica receives events.
- Public documents and claims are approved for publication.
- SEO baseline is checked.

## Week 4: QA, AI Search Check, Handover

Goal: complete QA and transfer operational control.

Planned work:

- Full QA of public user scenarios.
- Frontend responsive checks.
- Forms and CRM handoff checks.
- Admin/CMS checks.
- AI-search quality check over approved documentation.
- Post-production E2E checks.
- Prepare access inventory and credentials handover act.
- Transfer repository, stand, admin, hosting, and operational documentation.

Acceptance gate:

- Critical scenarios pass QA.
- Credentials/accesses are transferred or ownership is confirmed.
- Final act and acceptance documents are ready.
- Customer has enough access to operate the project after completion.
