# admin

**Русский** · [English](README.en.md)

Админское API — двери правки и CRM: `/api/admin/v1/**`.

Одна из трёх дверей портала. Раньше это были серверные страницы на Thymeleaf,
теперь JSON, поверх которого работает админка на Next.js. Страницы удалены,
и вместе с ними у портала не осталось ни одной страницы для браузера — а значит
ни формы входа, ни cookie-сессии, ни CSRF-токена, который надо было бы
защищать.

Здесь **только транспорт**. Правила живут в доменах: `CatalogEditor`,
`ContentEditor`, `DocumentEditor`, `LeadTriage`, `ClientDesk`, `DealDesk`,
`QuoteDesk`, `HistoryDesk`, `Pipelines`. Правило, записанное в контроллере,
действует ровно до появления второго транспорта — импорта, теста, второй двери.

Что модуль делает сам:

- разбирает, **кто** совершил действие (`Actor`): у токена Keycloak
  `Principal.getName()` — это `sub`, то есть UUID, и журнал по нему
  не читается. Берётся `preferred_username`, с запасными вариантами;
- ограничивает размер страницы сверху там, где отдаются персональные данные:
  заявки, клиенты, сделки, КП. `?size=1000000` не должен превращать список
  в выгрузку всей базы одним запросом.

Контракт целиком — [docs/api/vedal-admin-openapi.yaml](../../docs/api/vedal-admin-openapi.yaml)
и [коллекция Postman](../../docs/api/vedal.postman_collection.json).

## Модуль сборки

`portal-admin` — модуль Maven со своим `pom.xml` и своим `src/`. Зависит от:
`common`, `audit`, `catalog`, `content`, `crm`, `documents`.

Самый связанный модуль, и это нормально: админка — одна дверь во все домены.
Видит она только их `*Admin`-интерфейсы.

Границу держит сборка, а не дисциплина: импорт из модуля, которого нет
в зависимостях, роняет компиляцию. Раньше весь код лежал одной кучей
в `backend/src/`, и удержать границы можно было только вниманием.
