# gateway

**Русский** · [English](README.en.md)

Integration Gateway — единственная дверь, через которую внешние обращения попадают
в CRM. Из [брифа собственника](../../docs/architecture/vedal_portal_owner_brief.md):
«контролируемый gateway между системами», «правила, approve, аудит».

Что делает:

- Принимает заявку из формы сайта, Яндекс Формы или корпоративной почты.
- Проверяет источник, состав полей и вложения.
- Создаёт в CRM черновик лида — без автоматического доступа к закрытым данным.
- Пишет каждое обращение в [audit](../audit/).

Что не делает: не хранит клиентскую базу и не отдаёт данные наружу.

Формы, которые придут отсюда, описаны в
[content_model.md](../../docs/frontend/content_model.md) → Lead Form Model:
КП, каталог, консультация, сервис, партнёрство.

Сейчас формы во фронтенде собраны, но отправлять некуда — `frontend/components/LeadForm.tsx`
ждёт этот модуль.

## Модуль сборки

`portal-gateway` — модуль Maven со своим `pom.xml` и своим `src/`. Зависит от: `common`, `crm`.

Зависимость от `crm` — это `LeadIntake`, и только он: ни сущности, ни
репозитория заявки дверь не видит.

Границу держит сборка, а не дисциплина: импорт из модуля, которого нет
в зависимостях, роняет компиляцию. Раньше весь код лежал одной кучей
в `backend/src/`, и удержать границы можно было только вниманием.
