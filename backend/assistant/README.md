# assistant

Публичный ассистент Urania. Спецификация —
[urania_assistant_spec.md](../../docs/strategy/urania_assistant_spec.md),
место в архитектуре —

Код: `src/main/java/ru/vedal/portal/assistant/`.

Дверь одна: `POST /api/assistant/v1/ask`. Ответ несёт текст и список источников.

## Почему ограничения не в промпте

Жёсткие запреты — не диагностировать, не рекомендовать лечение, не выдумывать
цены, сроки, характеристики и статусы регистрации — живут в `Guardrails`, до
вызова движка. Промпт — это просьба к модели, а не гарантия; проверка перед
движком не зависит от того, какая модель стоит за портом.

Отдельная ловушка: границу слова `\b` в Java задаёт `UNICODE_CHARACTER_CLASS`,
то есть флаг `(?U)`. Со строчной `u` (`UNICODE_CASE`) правила по кириллице
**молча не срабатывают**. `GuardrailsTest` это проверяет.

## Почему закрытые материалы недостижимы

`LlmEngine` ходит только через интерфейсы соседей — `CatalogQuery`,
`ContentQuery`, `DocumentQuery`, — а они отдают исключительно опубликованное.
Неопубликованное изделие, черновик новости и несогласованный документ в контекст
ответа не попадают физически, поэтому уговорить ассистента их показать нельзя.

Нет подходящих источников — ответа нет: идёт передача человеку с контактами
и списком форм. Придумывать ответ запрещено.

## Порт и что будет дальше

`LlmEngine` сейчас — детерминированный поиск по словам, без модели. Полная
реализация: YandexGPT + pgvector, конвейер из спеки (извлечение текста → чанки
с метаданными → эмбеддинги). Домены за порт не заглядывают, смена реализации
их не тронет.

В журнал пишется исход обращения и число источников, **без текста вопроса**:
посетитель может указать в нём и клинику, и себя.
