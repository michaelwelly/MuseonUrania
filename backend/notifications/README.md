# notifications

**Русский** · [English](README.en.md)

Исходящие письма: подтверждение клиенту, уведомление ответственному менеджеру.

Ограничение из [брифа собственника](../../docs/architecture/vedal_portal_owner_brief.md),
шаг «Ответ клиенту»: наружу уходит только шаблонное письмо или согласованный
документ. Свободный текст с коммерческими условиями через этот модуль не отправляется.

Транспорт — корпоративная почта Яндекс 360, её покупаем. Здесь шаблоны, очередь
отправки и учёт доставки.

Текст подтверждения из [content_model.md](../../docs/frontend/content_model.md):
«Спасибо. Специалист VEDAL свяжется с вами.»

## Модуль сборки

`portal-notifications` — модуль Maven со своим `pom.xml` и своим `src/`. Зависит от: `common`, `crm`.

Зависимость от `crm` — это `LeadContacts`: адрес получателя берётся по
идентификатору, чтобы персональные данные не уезжали в топики.

Границу держит сборка, а не дисциплина: импорт из модуля, которого нет
в зависимостях, роняет компиляцию. Раньше весь код лежал одной кучей
в `backend/src/`, и удержать границы можно было только вниманием.
